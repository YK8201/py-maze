# 第4章 壁まで滑らせる：if を while に変えるだけ

このゲームの主役の動き「壁にぶつかるまで滑る」を作ります。変えるのは `move` メソッドの1語だけです。

## コードを書きかえる

`move` メソッドの `if` を `while` に変えます。コメントも書きかえておきましょう。

```python
    def move(self, dx, dy):
        # となりが壁でないあいだ、ずっと進む（＝壁まで滑る）
        while not self.is_wall(self.x + dx, self.y + dy):
            self.x += dx
            self.y += dy
```

実行して矢印キーを押すと、プレイヤーが壁の手前まで一気に移動します。

## while は「条件が成り立つあいだ、くり返す」

`if` は条件が成り立てば1回だけ実行します。`while` は条件が成り立つあいだ、何度でもくり返します。

このコードは「となりが壁でないあいだ、1マス進む」をくり返しています。進むたびに `self.x` と `self.y` が変わるので、「となり」も1マスずつ先にずれていきます。壁の手前まで来ると条件が成り立たなくなり、くり返しが終わります。

くり返しは1フレームの中で全部終わってしまうので、画面ではプレイヤーが一瞬で移動したように見えます。途中の動きを見せるアニメーションは第9章で作ります。

## まわりを壁で囲む理由

第2章で「迷路のまわりを必ず `#` で囲む」とお願いしました。その理由がここにあります。

もし右端の壁が1か所欠けていたら、プレイヤーは迷路の外まで滑っていきます。外側にはマスがないので、`self.grid[y][x]` が範囲の外を読もうとして `IndexError` で止まります。

左や上に欠けがあるときは、もっとややこしいことが起きます。Python のリストは `-1` 番を「最後の要素」として読めてしまうので、エラーにならず、反対側の端に回りこんだような動きになります。エラーが出ないぶん、原因を見つけにくいバグです。

まわりがすべて壁なら、滑っている途中で必ずどこかの壁にぶつかります。くり返しが終わらなくなる心配もありません。
