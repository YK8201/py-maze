# 第14章 迷わせても理不尽にならない湖のつくりかた

自分でステージを作るようになると、すぐに2つの壁にぶつかります。簡単すぎてすぐ解けてしまう湖と、知らないうちに町へ行けなくなっている湖です。

いいステージは、プレイヤーを **迷わせる** けれど、**理不尽ではない** ものです。迷うのは楽しいのですが、気づかないうちに詰んでいるのは楽しくありません。ここで「詰む」とは、まだ動けるのに、どう動いてももう町に行けない状態になることです。UNDO で戻ればやり直せますが、プレイヤーは自分が詰んでいることに気づかないまま、しばらく動き回ってしまいます。

この章では、詰みがどこから生まれるかを見たうえで、迷わせても詰まない湖を作るコツと、それをプログラムで確かめる方法を紹介します。最後に、詰みをわざと残すときに、詰んだことをプレイヤーに知らせる方法も紹介します。第13章の `solver.py` を使うので、先に第13章を終えておいてください。

## 詰みは「戻ってこられない移動」と「割れた氷」から生まれる

このゲームの移動は、行きと帰りが同じとはかぎりません。A から右に滑って B に止まったとしても、B から左に滑ると A を通り過ぎて、もっと先まで行ってしまうことがあります。A の左側に岩がなければ、A では止まれないからです。そのうえ、もろい氷は一度通ると割れて、その道は二度と使えなくなります。

この2つが重なると、詰みが生まれます。例を見てみましょう。左の岸がスタート、左上の岸が町です。

```
#E#####
# ##  #
#     #
Sx   ##
#     #
#     #
#######
```

スタートのすぐ右にもろい氷があるので、最初の1手でかならず割れます。ここで右、下、左と動くと、左下の角に着いて、この局面になります。

```
#E#####
# ##  #
#     #
 ~   ##
#     #
#P    #
#######
```

もう町には行けません。左下の角からは、下の2段の中しか動き回れません。上へ戻るには左の列を上へ滑るしかないのですが、その列のもろい氷はもう割れて水になっています。上へ滑ると落ちてしまいます。

この湖は、岩を1つ足すだけで直ります。下から2段目（岸は数えません）の、左の岸から2マス目に岩を置いてみます。

```
#E#####
# ##  #
#     #
Sx   ##
# #   #
#     #
#######
```

下から2段目を左へ滑ると、この岩の手前で止まれるようになります。そこから上へ滑れば、上の段に戻れます。割れた氷の列を通らなくても上へ戻れるので、どの順番で動いても、もう詰みません。

## 詰まないための条件：どの止まれる場所からでも、町へ行ける道が残る

プレイヤーが止まれる場所を全部書き出して、「ここからこの向きに滑るとここに止まる」という矢印でつないだ図を考えます。もろい氷がない湖なら、この図で **どの止まれる場所からでも、何回か滑れば町に着ける** とき、その湖は詰みません。

矢印の中には、行けるけれど直接は戻れない一方通行がまじっていてもかまいません。ぐるっと回り道をすれば戻れるなら、詰みにはなりません。実は、この「一方通行だけど、回れば戻れる」が、プレイヤーを迷わせるいちばんの材料になります。

もろい氷があると、遊んでいるうちに矢印の図そのものが変わってしまいます。そういう湖は頭で考えるだけでは確かめきれないので、この章の後半で作るプログラムを使ってください。

## 迷わせるコツ

### 町に入る「最後の1手」から考える

町は岸にあるので、町に入る滑り方は、町の正面の列（または行）をまっすぐ滑ることしかありません。その列のどこかで止まれる場所がなければ、町には行けません。まず「最後の1手をどこから滑るか」を決めて、そこに止まるための岩を置き、そこへ行く道を逆向きにたどって作っていくと、解ける湖を作りやすくなります。

### 一方通行を「回れば戻れる」形で入れる

一方通行の場所を見ると、プレイヤーは「ここに入ったら戻れないのでは」と警戒します。実際には回り道で戻れるようにしておけば、詰ませずに迷わせられます。

### 「近くて遠い町」にする

町がすぐそこに見えるのに、手前で止まれないせいで、湖をぐるっと一周しないと入れない形です。プレイヤーは「どこから入ればいいのか」をじっくり考えることになります。

### 水は「通れない道」として置く

水は、入ると落ちますが、落ちた手は取り消されるので、水だけで詰むことはありません。そのかわり、「この列を滑ると落ちる」という通れない道を作れます。近道に見える列に水を置くと、プレイヤーはうっかり落ちながら、本当の道を探すことになります。

### 岩を増やすのは、ほどほどに

岩を置くと、その手前に止まれる場所が増えて、選べる手が増えます。ただし、岩が多すぎると、どこでも止まれて、かえって簡単になります。止まれる場所が少ない湖のほうが、1手の重みが大きくなります。

### もろい氷は「一度しか通らない近道」にする

もろい氷を通らないと行けない場所があると、詰みの原因になります。さきほどの例がまさにそうでした。安全なのは、遠回りの道が別にある「近道」に置くことです。近道を使えば手数は減りますが、使うタイミングを考える必要があります。

## プログラムで確かめる：詰みチェッカー

ここまでのコツを守っても、湖が大きくなると、頭で考えるだけでは見落としが出ます。そこで、第13章の `solver.py` の部品を使って、詰みを探すプログラムを作ります。

`solver.py` は、ほかのファイルから部品として使える形になっています。最後の、全ステージを解いて表示する部分が `if __name__ == "__main__":` の中に入っているからです。この中は、そのファイルを `python solver.py` で直接実行したときだけ動き、ほかのファイルから `import` したときには動きません。

同じフォルダに `checker.py` を作ります。

```python
# 湖が「詰むか」と「どれくらい迷うか」を調べるプログラム
# solver.py・levels.py と同じフォルダに置いて、python checker.py で実行する
import random
from collections import deque

from levels import LEVELS
from solver import DIRECTIONS, make_key, slide, solve, start_state


def all_states(level):
    """スタートからたどり着ける局面を全部集める。
    戻り値は (スタートの局面, 局面ごとの湖, 局面ごとの「次の局面のリスト」)。
    町に着く動きは、次の局面を "CLEAR" と書いておく"""
    grid, x, y = start_state(level)
    start = make_key(grid, x, y)
    boards = {start: (grid, x, y)}
    nexts = {}
    queue = deque([start])
    while queue:
        key = queue.popleft()
        grid, x, y = boards[key]
        nexts[key] = []
        for dx, dy in DIRECTIONS.values():
            result = slide(grid, x, y, dx, dy)
            if result is None:
                continue
            new_grid, nx, ny, won = result
            if won:
                nexts[key].append("CLEAR")
                continue
            new_key = make_key(new_grid, nx, ny)
            nexts[key].append(new_key)
            if new_key not in boards:
                boards[new_key] = (new_grid, nx, ny)
                queue.append(new_key)
    return start, boards, nexts


def find_ok(nexts):
    """町につながる局面の集合を返す。これに入らない局面は詰んでいる"""
    ok = set()
    changed = True
    while changed:  # 「町につながる局面」が増えなくなるまでくり返す
        changed = False
        for key, next_keys in nexts.items():
            if key in ok:
                continue
            for n in next_keys:
                if n == "CLEAR" or n in ok:
                    ok.add(key)
                    changed = True
                    break
    return ok


def wander(start, nexts, ok, players=300, limit=3000):
    """でたらめに動くプレイヤーが、町に着くまでに平均何手かかるか。
    詰んだらスタートからやり直す（手数はそのまま数え続ける）"""
    total = 0
    for _ in range(players):
        key = start
        moves = 0
        while moves < limit:
            if len(nexts[key]) == 0:  # どこにも動けない
                key = start
                continue
            key = random.choice(nexts[key])
            moves += 1
            if key == "CLEAR":
                break
            if key not in ok:  # 詰んだらやり直し
                key = start
        total += moves
    return total / players


def show(grid, x, y):
    """局面を文字で表示する。P がプレイヤー"""
    for row_y, row in enumerate(grid):
        line = "".join(row)
        if row_y == y:
            line = line[:x] + "P" + line[x + 1 :]
        print("    " + line)


for i, level in enumerate(LEVELS):
    answer = solve(level)
    if answer is None:
        print(f"{i + 1} {level['name']}: 解けません！")
        continue
    start, boards, nexts = all_states(level)
    ok = find_ok(nexts)
    stuck = [key for key in nexts if key not in ok]
    score = wander(start, nexts, ok) / len(answer)
    print(f"{i + 1} {level['name']}: 局面 {len(nexts)}個  詰み {len(stuck)}個  迷い度 {score:.1f}")
    if stuck:
        # 詰んだ局面の例を1つ見せる（割れた氷が少ないものを選ぶ）
        key = min(stuck, key=lambda k: k[2].count("~"))
        print("  たとえばこの局面からは、もう町に行けません:")
        show(*boards[key])
```

このプログラムは、3つのことをしています。

1. **局面を全部集める**（`all_states`）。第13章の幅優先探索とほとんど同じですが、町に着いても止めずに、たどり着ける局面をすべて集めます。局面ごとに「1手で行ける次の局面」も記録しておきます
2. **町につながる局面を探す**（`find_ok`）。「次の局面に、クリアか『町につながる局面』がある局面」は、町につながる局面です。この判定を、新しく見つからなくなるまでくり返します。最後まで仲間に入れなかった局面が、詰んだ局面です
3. **迷い度を測る**（`wander`）。でたらめに動くプレイヤーを300人走らせて、町に着くまでにかかった手数の平均を出し、最短手数で割ります。最短で解ける人の何倍くらい手間取るかの目安になります。詰んだら（実際のプレイヤーが UNDO や RESET をするように）スタートからやり直させています

さきほどの例の2つの湖を `levels.py` に入れて実行すると、次のように表示されます。

```
1 BAD: 局面 11個  詰み 4個  迷い度 6.2
  たとえばこの局面からは、もう町に行けません:
    #E#####
    # ##  #
    #     #
     ~   ##
    #     #
    #P    #
    #######
2 FIXED: 局面 13個  詰み 0個  迷い度 7.0
```

詰む湖では、詰んだ局面の例として、さきほどの左下の角の局面と同じ形が表示されます（P がプレイヤー、左の岸のすき間がスタートの跡です）。岩を1つ足した湖では、詰みが0個になっています。

## 詰みをなくすか、詰んだことを教えるか

レイトン教授の「氷の湖」のナゾにも、行き止まりになる道があります。このナゾの面白さは「どの順番で氷を割るか」にあるので、詰む局面を全部なくそうとすると、かえって物足りなくなることもあります。

そこで、もう1つのやり方があります。詰む局面は残しておき、詰んだらすぐにゲームが教えてあげるのです。このリポジトリの完成版のゲームは、詰んだ瞬間に「STUCK」と表示します。プレイヤーは気づかずに動き回ることがなくなり、UNDO で戻って別の順番を試せます。

この教材のゲームにも足してみましょう。`solver.py` を `main.py` と同じフォルダに置き、`main.py` の最初で部品を読みこみます。

```python
from solver import DIRECTIONS, make_key, slide
```

`App` に、今の局面から町へ行けるかを調べるメソッドを足します。第13章の幅優先探索と同じ考え方で、たどり着ける局面を順に調べ、町に着く手が1つでも見つかれば「詰んでいない」とします。

```python
    def is_stuck(self):
        """今の局面から、もう町に行けなければ True"""
        key = make_key(self.grid, self.x, self.y)
        if key in self.stuck_memo:  # 一度調べた局面は、覚えておいた答えを使う
            return self.stuck_memo[key]
        seen = {key}
        todo = [(self.grid, self.x, self.y)]
        stuck = True
        while todo and stuck:
            grid, x, y = todo.pop()
            for dx, dy in DIRECTIONS.values():
                result = slide(grid, x, y, dx, dy)
                if result is None:
                    continue
                new_grid, nx, ny, won = result
                if won:
                    stuck = False
                    break
                new_key = make_key(new_grid, nx, ny)
                if new_key not in seen:
                    seen.add(new_key)
                    todo.append((new_grid, nx, ny))
        self.stuck_memo[key] = stuck
        return stuck
```

`draw` は毎フレーム呼ばれるので、そのたびに調べ直すとむだが多くなります。そこで、調べた答えを `self.stuck_memo` という辞書に覚えておき、同じ局面ではそれを使います。`__init__` で `self.stuck_memo = {}` と空の辞書を作っておいてください。

最後に、`draw` の最後で、滑っている最中でもクリアしたあとでもないときに、詰んでいたら文字を出します。

```python
        if not self.moving and not self.clear and self.is_stuck():
            pyxel.text(30, 130, "STUCK! PRESS UNDO", 8)
```

7番目の CRACKS などで、わざと詰む順番に動いてみてください。詰んだ瞬間に文字が出て、UNDO で戻ると消えるはずです。

## ステージを作る手順

1. 小さめ（7×7くらい）の湖を描く。スタートと町は岸に置く
2. `solver.py` で、解けるか、最短何手かを調べる。解けなければ、町に入る最後の1手を見直す
3. `checker.py` で詰みを探す。見つかったら、表示された局面を見て、どこへ戻れなくなったのかを考え、岩を足したり、もろい氷の場所を変えたりする。詰みを残すなら、STUCK の表示を入れておく
4. 迷い度を見ながら、一方通行や水の罠を足していく
5. 最後に、自分で遊んで確かめる

このリポジトリの完成版のステージは、この手順をプログラムで自動化して作りました。`tools/gen_levels.py` がランダムに湖を作り、迷い度が高く、うっかり落ちる危険もほどよくあるものを選んでいます。考え方は、この章で作った `checker.py` と同じです。
