# 第14章 迷わせても詰まない迷路のつくりかた

自分でステージを作るようになると、すぐに2つの壁にぶつかります。簡単すぎてすぐ解けてしまう迷路と、知らないうちに解けなくなっている迷路です。

いいステージは、プレイヤーを **迷わせる** けれど **詰ませない** ものです。迷うのは楽しいのですが、詰むのは楽しくありません。ここで「詰む」とは、まだ動けるのに、どう動いてももうクリアできない状態になることです。UNDO で戻ればやり直せますが、プレイヤーは自分が詰んでいることに気づかないまま、しばらく動き回ってしまいます。それはパズルの難しさではなく、作りの不親切さです。

この章では、詰みがどこから生まれるかを見たうえで、迷わせても詰まない迷路を作るコツと、それをプログラムで確かめる方法を紹介します。第13章の `solver.py` を使うので、先に第13章を終えておいてください。

## 詰みは「戻ってこられない移動」から生まれる

このゲームの移動は、行きと帰りが同じとはかぎりません。A から右に滑って B に止まったとしても、B から左に滑ると A を通り過ぎて、もっと先まで行ってしまうことがあります。A の左側に壁がなければ、A では止まれないからです。

戻ってこられない移動が、ドットの残っている場所から離れる向きにあると、詰みが生まれます。例を見てみましょう。

```
#######
#  #  #
##S   #
#E ####
#     #
#######
```

スタートから下に滑ると、左下のゴールのあたりに着きます。下の段からは、左上の角までは戻れます。ところが、右上の部屋にはもう二度と行けません。右上へ行く道は、真ん中の段に止まってから右へ滑るしかないのですが、下からまっすぐ上がってくると真ん中の段を通り過ぎてしまい、止まれないからです。

最初に下へ行ってしまうと、右上のドットを残したまま、この局面になります。もうクリアできません。

```
#######
#  #. #
##    #
#E ####
#    P#
#######
```

スタート地点は、こういう「最初の1回しか立てない場所」になりやすいので注意が必要です。

この迷路は、壁を1つ取るだけで直ります。上の段のまん中にある `#` を取って、上の段を1本の通路にしてみます。

```
#######
#     #
##S   #
#E ####
#     #
#######
```

下から上がってきて上の段に止まったあと、右へ滑れば右上の角まで行けます。そこから右上の部屋に戻れるので、どの順番で動いても、もう詰みません。

## 詰まないための条件：どの止まれる場所からでも、ほかの全部の止まれる場所へ行ける

プレイヤーが止まれる場所を全部書き出して、「ここからこの向きに滑るとここに止まる」という矢印でつないだ図を考えます。この図で、**どの止まれる場所からでも、ほかのすべての止まれる場所へ、何回か滑ればたどり着ける** なら、その迷路は詰みません。どんな順番でドットを拾っていても、残ったドットのある場所へ必ず行けるからです。

矢印の中には、行けるけれど直接は戻れない一方通行がまじっていてもかまいません。ぐるっと回り道をすれば戻れるなら、詰みにはなりません。実は、この「一方通行だけど、回れば戻れる」が、プレイヤーを迷わせるいちばんの材料になります。

崩れる床があると、遊んでいるうちに矢印の図そのものが変わってしまいます。崩れる床を使うときは、この条件を頭で考えるだけでは足りないので、この章の後半で作るプログラムで確かめてください。

## 迷わせるコツ

### 一方通行を「回れば戻れる」形で入れる

一方通行の通路を見ると、プレイヤーは「ここに入ったら戻れないのでは」と警戒します。実際には回り道で戻れるようにしておけば、詰ませずに迷わせられます。

### 「近くて遠いマス」を作る

すぐ隣に見えるのに、手前で止まれないせいで、ぐるっと遠回りしないと通れないマスです。最後の1個のドットがこういうマスにあると、プレイヤーは「どこから入ればいいのか」をじっくり考えることになります。

### 止まれる場所を増やすのは、ほどほどに

通路の途中に壁を1つ置くと、その手前に止まれる場所が増えて、選べる手が増えます。ただし、広い部屋に壁がたくさんあると、どう動いてもだいたい全部通れてしまい、かえって簡単になります。通路の多い迷路のほうが、1手の重みが大きくなります。

### ゴールを通り道に置く

ドットが残っているあいだ、ゴールはただの床です。何度も通る通路の途中にゴールを置くと、プレイヤーは最後に「どの向きからゴールに入るか」まで考える必要が出てきます。

### ぬかるみで「止まれない場所」に止まらせる

ぬかるみは、通路の途中に止まれる場所を作ります。ぬかるみに止まると、そこから横に曲がれるようになります。ぬかるみを通り抜けたいときにも止まってしまうので、通路が一方通行のようにふるまうことにも注意してください。

### 崩れる床は「一度しか通らない近道」にする

崩れる床は、通ったあとに壁になります。その床を通らないと行けない場所があると、詰みの原因になります。崩れる床は、遠回りの道が別にある「近道」に置くのが安全です。近道を使うと手数は減りますが、使うタイミングを考える必要があります。

## プログラムで確かめる：詰みチェッカー

ここまでのコツを守っても、迷路が大きくなると、頭で考えるだけでは見落としが出ます。そこで、第13章の `solver.py` の部品を使って、詰みを探すプログラムを作ります。

まず `solver.py` を、ほかのファイルから部品として使える形にしておきます（`code/extra/solver.py` は、この形になっています）。変更点は2つです。

- 迷路を準備する処理を `start_state` 関数に、局面を表す値を作る処理を `make_key` 関数に分ける
- 最後の、全ステージを解いて表示する部分を `if __name__ == "__main__":` の中に入れる

`if __name__ == "__main__":` の中は、そのファイルを `python solver.py` で直接実行したときだけ動きます。ほかのファイルから `import` したときには動きません。これで、`solver.py` の関数だけを借りられるようになります。

そのうえで、同じフォルダに `checker.py` を作ります。

```python
# 迷路が「詰まないか」と「どれくらい迷うか」を調べるプログラム
# solver.py・levels.py と同じフォルダに置いて、python checker.py で実行する
import random
from collections import deque

from levels import LEVELS
from solver import DIRECTIONS, make_key, slide, solve, start_state


def all_states(level):
    """スタートからたどり着ける局面を全部集める。
    戻り値は (スタートの局面, 局面ごとの迷路, 局面ごとの「次の局面のリスト」)。
    クリアになる動きは、次の局面を "CLEAR" と書いておく"""
    grid, x, y = start_state(level)
    start = make_key(grid, x, y)
    boards = {start: (grid, x, y)}
    nexts = {}
    queue = deque([start])
    while queue:
        key = queue.popleft()
        grid, x, y = boards[key]
        nexts[key] = []
        for dx, dy in DIRECTIONS.values():
            result = slide(grid, x, y, dx, dy)
            if result is None:
                continue
            new_grid, nx, ny, won = result
            if won:
                nexts[key].append("CLEAR")
                continue
            new_key = make_key(new_grid, nx, ny)
            nexts[key].append(new_key)
            if new_key not in boards:
                boards[new_key] = (new_grid, nx, ny)
                queue.append(new_key)
    return start, boards, nexts


def find_stuck(nexts):
    """もうクリアできない（詰んだ）局面のリストを返す"""
    ok = set()  # クリアにつながる局面
    changed = True
    while changed:  # 「クリアにつながる局面」が増えなくなるまでくり返す
        changed = False
        for key, next_keys in nexts.items():
            if key in ok:
                continue
            for n in next_keys:
                if n == "CLEAR" or n in ok:
                    ok.add(key)
                    changed = True
                    break
    return [key for key in nexts if key not in ok]


def wander(start, nexts, players=300, limit=2000):
    """でたらめに動くプレイヤーが、クリアまでに平均何手かかるか"""
    total = 0
    for _ in range(players):
        key = start
        moves = 0
        while moves < limit:
            if len(nexts[key]) == 0:  # どこにも動けない
                moves = limit
                break
            key = random.choice(nexts[key])
            moves += 1
            if key == "CLEAR":
                break
        total += moves
    return total / players


def show(grid, x, y):
    """局面を文字で表示する。P がプレイヤー"""
    for row_y, row in enumerate(grid):
        line = "".join(row)
        if row_y == y:
            line = line[:x] + "P" + line[x + 1 :]
        print("    " + line)


for i, level in enumerate(LEVELS):
    answer = solve(level)
    if answer is None:
        print(f"{i + 1} {level['name']}: 解けません！")
        continue
    start, boards, nexts = all_states(level)
    stuck = find_stuck(nexts)
    score = wander(start, nexts) / len(answer)
    print(f"{i + 1} {level['name']}: 局面 {len(nexts)}個  詰み {len(stuck)}個  迷い度 {score:.1f}")
    if stuck:
        # 詰んだ局面の例を1つ見せる（残りのドットが少ないものを選ぶ）
        key = min(stuck, key=lambda k: k[2].count("."))
        print("  たとえばこの局面は、もうクリアできません:")
        show(*boards[key])
```

このプログラムは、3つのことをしています。

1. **局面を全部集める**（`all_states`）。第13章の幅優先探索とほとんど同じですが、クリアが見つかっても止めずに、たどり着ける局面をすべて集めます。局面ごとに「1手で行ける次の局面」も記録しておきます
2. **詰んだ局面を探す**（`find_stuck`）。「次の局面に、クリアか『クリアにつながる局面』がある局面」は、クリアにつながる局面です。この判定を、新しく見つからなくなるまでくり返します。最後まで仲間に入れなかった局面が、詰んだ局面です
3. **迷い度を測る**（`wander`）。でたらめに動くプレイヤーを300人走らせて、クリアまでにかかった手数の平均を出し、最短手数で割ります。最短で解ける人の何倍くらい手間取るかの目安になります

さきほどの例の迷路2つを `levels.py` に入れて実行すると、次のように表示されます。

```
1 BAD: 局面 189個  詰み 135個  迷い度 140.1
  たとえばこの局面は、もうクリアできません:
    #######
    #  #. #
    ##    #
    #E ####
    #    P#
    #######
2 FIXED: 局面 184個  詰み 0個  迷い度 5.8
```

詰みのある迷路は、でたらめに動くと詰んだまま抜け出せなくなるので、迷い度がとても大きくなります。

## 迷い度の目安

この教材のステージを `checker.py` で測ると、迷い度は次のようになりました。

| ステージ | 最短手数 | 局面の数 | 詰み | 迷い度 |
| --- | --- | --- | --- | --- |
| 1 SLIDE | 3 | 6 | 0 | 2.9 |
| 2 TURN | 5 | 15 | 0 | 5.0 |
| 3 CORRIDOR | 8 | 60 | 0 | 5.2 |
| 4 FORK | 10 | 84 | 0 | 10.9 |
| 5 DETOUR | 13 | 1273 | 0 | 8.2 |
| 6 MUD | 6 | 78 | 0 | 7.3 |
| 7 STOPOVER | 12 | 115 | 0 | 7.7 |
| 8 CRUMBLE | 6 | 58 | 0 | 5.3 |
| 9 ONE WAY | 9 | 91 | 0 | 7.1 |
| 10 MIRE | 20 | 548 | 0 | 39.5 |

一本道に近い SLIDE は3くらい、迷いどころのあるステージは5〜11くらいです。MIRE は詰みが0個なのに、40前後と飛びぬけて大きくなっています。でたらめに動くと同じ場所を何度も行き来してしまい、全部のマスを通り終えるまでに時間がかかる形をしているためだと考えられます。迷い度は、詰みがなくても大きくなることがあるわけです。詰んでいるかどうかは、迷い度ではなく詰みの個数で判断してください。

詰み0個のまま迷い度を上げていくのが、ステージ作りの目標になります。迷い度はでたらめなプレイヤーで測るので、実行するたびに少し変わります。

## ステージを作る手順

1. 小さめ（7×7くらい）の迷路を描く。まわりは壁で囲む
2. `solver.py` で、解けるか、最短何手かを調べる。解けなければ、滑っても通れないマスがないかを探す（第5章）
3. `checker.py` で詰みを探す。見つかったら、表示された局面を見て、どこへ戻れなくなったのかを考え、壁を足したり取ったりする
4. 詰みが0個になったら、迷い度を見ながら、一方通行や近くて遠いマスを足していく
5. 最後に、自分で遊んで確かめる

このリポジトリの完成版のステージは、この手順をプログラムで自動化して作りました。`tools/gen_levels.py` がランダムに迷路を作り、詰みが0個で迷い度の高いものを選んでいます。考え方は、この章で作った `checker.py` と同じです。
